# Bulls and Cows — Техническая документация

## 1. Структуры данных и алгоритмы

### 1.1. Состояние игры (Game State)

Состояние игры представлено интерфейсом `GameState`:

```ts
interface GameState {
  secret: string;
  history: Turn[];
  settings: Settings;
  status: Status;
  time: number;
}
```

Состояние содержит:

- `secret` — загаданное число, генерируемое в начале игры.
- `history` — массив всех предыдущих попыток.
- `settings` — настройки игры: выбранная система счисления и длина загаданного числа.
- `status` — текущее состояние игры (`PROGRESS` или `FINISHED`).
- `time` — время игры в секундах.

Все данные, относящиеся к одной игровой сессии, объединены в один объект. Это упрощает управление состоянием, передачу данных между модулями и обновление пользовательского интерфейса.

### 1.2. История попыток

История попыток хранится в массиве объектов `Turn`:

```ts
interface Turn {
  guess: string;
  result: EvaluationResult;
}

interface EvaluationResult {
  bulls: number;
  cows: number;
}
```

Массив выбран по следующим причинам:

- Попытки должны сохранять порядок их выполнения.
- Количество попыток заранее неизвестно.
- Новые попытки добавляются в конец массива.
- Историю необходимо отображать в хронологическом порядке.

История обновляется иммутабельно — вместо изменения существующего массива создаётся новый:

```ts
const updatedHistory = [...state.history, turn];
```

Это позволяет сохранять предыдущие версии состояния неизменными, упрощает тестирование и делает изменения состояния более предсказуемыми.

`bulls` и `cows` содержат количество совпадающих цифр.

### 1.3. Системы счисления

Поддерживаемые системы счисления представлены перечислением `Base`:

- `BIN` — двоичная.
- `OCT` — восьмеричная.
- `DEC` — десятичная.
- `HEX` — шестнадцатеричная.

Конфигурация каждой системы централизована в объекте:

```ts
BaseConfig: Record<Base, BaseObject>;
```

Для каждой системы определены:

- Максимально допустимая длина загаданного числа.
- Список доступных символов.
- Название системы счисления для отображения.

Централизация конфигурации позволяет избежать дублирования правил в разных частях приложения и упрощает добавление новых систем счисления.

### 1.4. Алгоритм `generateSecret`

Функция `generateSecret(length, base, random)` генерирует случайное число заданной длины в выбранной системе счисления.

Алгоритм должен обеспечивать следующие условия:

1. Используются только символы, допустимые для выбранной системы счисления.
2. Все символы уникальны.
3. Начальные нули сохраняются.
4. Генератор случайных чисел можно передать в функцию извне для детерминированного тестирования.

Загаданное число хранится в виде строки, а не числового типа. Это необходимо для сохранения ведущих нулей и поддержки шестнадцатеричных символов.

Возможность передать собственную функцию генерации случайных чисел отделяет алгоритм от конкретного источника случайности. В production используется `Math.random`, а в тестах можно передать детерминированную функцию.

### 1.5. Алгоритм `evaluateGuess`

Функция `evaluateGuess(secret, guess)` сравнивает попытку игрока с загаданным числом.

Результат сравнения состоит из двух типов совпадений:

- **Бык (Bull)** — цифра присутствует в загаданном числе и находится на той же позиции.
- **Корова (Cow)** — цифра присутствует в загаданном числе, но находится на другой позиции.

Алгоритм выполняет следующие действия:

1. Последовательно перебирает символы попытки.
2. Сравнивает каждый символ с символом загаданного числа на той же позиции.
3. Если символы совпадают, значение `bulls` увеличивается на 1.
4. Если символы не совпадают, проверяется наличие этого символа в загаданном числе на другой позиции.
5. Если символ найден, значение `cows` увеличивается на 1.

Пример:

```text
Загаданное число: 4271
Попытка:           4723

bulls:  0
cows: 2
```

Для шестнадцатеричной системы сравнение символов выполняется без учёта регистра. Исходные строки при этом не изменяются.

### 1.6. Алгоритм `isValidGuess`

Функция `isValidGuess(guess, length, base)` проверяет соответствие попытки правилам игры.

Проверяются три условия:

1. Длина попытки соответствует заданной длине числа.
2. Все символы входят в список допустимых символов выбранной системы счисления.
3. В попытке отсутствуют повторяющиеся символы.

Для проверки уникальности используется структура данных `Set`. Она хранит только уникальные значения и обеспечивает в среднем константное время проверки наличия элемента.

Отделение валидации от алгоритма сравнения позволяет не передавать некорректные данные в `evaluateGuess`.

### 1.7. Алгоритм `countPossibleSecrets`

Функция `countPossibleSecrets(length, base)` вычисляет количество возможных уникальных чисел для заданной длины и системы счисления.

Поскольку повторение символов запрещено, задача сводится к вычислению числа размещений без повторений.

Если:

- `B` — количество доступных символов в выбранной системе счисления;
- `L` — длина загаданного числа;

то количество возможных комбинаций вычисляется по формуле:

P(B,L)= B! / (B-L)!

Например, для десятичной системы счисления и длины числа 3:

P(10,3)=10 × 9 × 8=720

В реализации используется рекурсивное вычисление с мемоизацией. Промежуточные результаты сохраняются, чтобы избежать повторного выполнения одинаковых вычислений.

Функция также должна учитывать граничные случаи, например нулевую длину, и проверять допустимость заданной длины для выбранной системы счисления.

## 2. Оценка сложности алгоритмов (Big O)

Для оценки сложности используются следующие обозначения:

- `L` — длина загаданного числа или попытки.
- `B` — количество доступных символов в выбранной системе счисления.

### 2.1. `generateSecret` — O(L × B)

Алгоритм выбирает символы из доступного алфавита без повторений.

Если выбранный символ удаляется из массива доступных символов с помощью `splice`, операция удаления требует сдвига оставшихся элементов и может занимать до \(O(B)\).

Такое действие выполняется `L` раз:

O(L × B)

Для хранения массива доступных символов требуется \(O(B)\) дополнительной памяти.

### 2.2. `evaluateGuess` — O(L²)

Алгоритм перебирает каждый символ попытки.

Для каждого символа может выполняться поиск в загаданном числе с помощью `includes()`. Такая операция в худшем случае требует \(O(L)\) времени.

Поскольку поиск выполняется для каждого из `L` символов:

O(L × L)=O(L²)

### 2.3. `isValidGuess` — O(L)

Алгоритм проверяет длину строки, допустимость символов и отсутствие повторений.

Построение `Set` из строки длиной `L` занимает \(O(L)\). Проверка наличия элемента в `Set` в среднем выполняется за \(O(1)\).

Следовательно, общая временная сложность составляет:

O(L)

Для хранения множества уникальных символов требуется \(O(L)\) дополнительной памяти.

### 2.4. `countPossibleSecrets` — O(L)

При использовании мемоизации промежуточные результаты сохраняются и повторно используются.

Каждое уникальное состояние рекурсивного вычисления обрабатывается не более одного раза. Если количество таких состояний пропорционально `L`, временная сложность составляет \(O(L)\).

Для хранения промежуточных результатов требуется \(O(L)\) дополнительной памяти.

**Примечание:** приведённые оценки основаны на реализации генерации с удалением элементов массива, сравнении с помощью `includes()` и мемоизации по оставшейся длине. Если фактические реализации отличаются, оценки необходимо скорректировать.

## 3. Применение принципов Clean Code

При разработке проекта применялись принципы Clean Code, направленные на повышение читаемости, сопровождаемости и тестируемости кода.

### 3.1. Принцип единственной ответственности (Single Responsibility Principle)

Каждый модуль и функция отвечают за определённую задачу.

Примеры:

- `src/game/logic/generateSecret.ts` — генерация загаданного числа.
- `src/game/logic/evaluateGuess.ts` — сравнение попытки с загаданным числом.
- `src/game/logic/isValidGuess.ts` — проверка корректности попытки.
- `src/game/logic/countPossibleSecrets.ts` — подсчёт возможных комбинаций.
- `src/game/logic/gameState.ts` — операции обновления состояния игры.

Также разделены игровая логика и пользовательский интерфейс: игровые модули реализуют правила игры, а модули экранов отвечают за создание и отображение DOM-элементов.

Такое разделение позволяет изменять пользовательский интерфейс, не затрагивая алгоритмы игры.

### 3.2. Осмысленные имена (Meaningful Names)

Названия функций, переменных и интерфейсов отражают их назначение.

Примеры:

- `generateSecret` — генерирует загаданное число.
- `evaluateGuess` — оценивает попытку.
- `countPossibleSecrets` — подсчитывает возможные числа.
- `EvaluationResult` — описывает результат сравнения.
- `GameState` — описывает состояние игровой сессии.

Осмысленные имена позволяют быстрее понять назначение кода без необходимости изучать дополнительные комментарии.

### 3.3. Избегание дублирования (Don't Repeat Yourself, DRY)

Правила систем счисления централизованы в `BaseConfig`.

Вместо повторного описания доступных символов, названий и максимальной длины в разных функциях используется единая конфигурация.

Например, максимальная длина числа получается через:

```ts
BaseConfig[base].maxLength;
```

Это упрощает поддержку проекта и позволяет изменять параметры системы счисления в одном месте.

### 3.4. Маленькие функции (Small Functions)

Функции выполняют небольшие, логически завершённые операции.

Например, в модуле стартового экрана:

- `createBaseDropdown()` создаёт список выбора системы счисления.
- `createEmptySecretLengthDropdown()` создаёт список выбора длины числа.
- `updateSelectLengthDropdownOptions()` обновляет доступные варианты длины.
- `updateCombinationsInfo()` пересчитывает и отображает количество возможных комбинаций.
- `getFormParameters()` извлекает параметры из формы.
- `startGame()` запускает новую игру с полученными параметрами.
- `openLeaderboard()` открывает таблицу рекордов с текущими настройками.

Разделение логики на небольшие функции упрощает чтение, тестирование и повторное использование кода.

### 3.5. Неизменяемость данных (Immutability)

При обновлении состояния игры существующие объекты и массивы не изменяются напрямую.

Например, при добавлении новой попытки создаётся новый массив истории:

```ts
const updatedHistory = [...state.history, turn];
```

Аналогичный подход применяется при обновлении состояния: создаётся новый объект с изменёнными свойствами.

Это помогает избежать побочных эффектов и делает переходы между состояниями предсказуемыми.

### 3.6. Избегание магических значений (Avoid Magic Numbers)

Параметры систем счисления централизованы в `BaseConfig`, а не разбросаны по функциям генерации и валидации.

Например, максимальная длина определяется через:

```ts
BaseConfig[base].maxLength;
```

Это позволяет изменять правила игры в одном месте и снижает вероятность несогласованности между модулями.

### 3.7. Внедрение зависимостей (Dependency Injection)

Функция `generateSecret` принимает генератор случайных чисел в качестве необязательного параметра.

Это позволяет отделить алгоритм генерации от конкретного источника случайности.

В основной версии приложения используется `Math.random`, а в тестах можно передать детерминированную функцию.

Благодаря этому тесты становятся воспроизводимыми и не зависят от случайных результатов.

### 3.8. Разделение ответственности между слоями (Separation of Concerns)

В проекте разделены игровая логика, управление состоянием и пользовательский интерфейс.

- Модули `game` содержат игровые правила и алгоритмы.
- Контроллер координирует игровые операции и изменения состояния.
- Модули экранов и компонентов создают и обновляют DOM.
- CSS Modules изолируют стили отдельных компонентов.

Такая архитектура позволяет изменять один слой приложения с минимальным влиянием на остальные.

### 3.9. Разработка через тестирование (Test-Driven Development, TDD)

Основные игровые функции разрабатывались с использованием подхода TDD:

1. Сначала создаётся тест, описывающий ожидаемое поведение.
2. Затем реализуется минимальный код, необходимый для прохождения теста.
3. После успешного прохождения тестов выполняется рефакторинг с сохранением работоспособности тестов.

Модульные тесты проверяют корректные и некорректные входные данные, особенности разных систем счисления, граничные условия и обновление состояния игры.

Внедрение генератора случайных чисел в `generateSecret` также позволяет проверять конкретные сценарии без зависимости от случайных значений.

## Заключение

В проекте используются простые и подходящие для игровой задачи структуры данных:

- Объекты — для хранения состояния игры и настроек.
- Массивы — для хранения истории попыток в хронологическом порядке.
- `Set` — для проверки уникальности символов.
- Мемоизация — для предотвращения повторных вычислений.

При разработке применялись принципы единственной ответственности, неизменяемости данных, осмысленного именования, разделения ответственности, внедрения зависимостей и разработки через тестирование.

В результате код становится более понятным, предсказуемым, тестируемым и удобным для дальнейшего расширения.
